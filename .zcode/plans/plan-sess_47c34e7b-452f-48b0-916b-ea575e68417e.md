## Root cause (verified by clean login-shell simulation)
`~/.zprofile`, `~/.zshrc`, and `~/.bash_profile` are all **MISSING**, and `/opt/homebrew/bin` is in **none** of `/etc/paths` or `/etc/paths.d/*`. So in a real Terminal.app window, nothing adds Homebrew to PATH → `brew` (and everything brew-installed: `node`, `npm`, `bun`, `gh`, `codemap`, `codex`, `gemini`, etc.) is `command not found`. The `claude` CLI shim (`~/.local/bin/claude`) is also gone. Prior "brew works" conclusions were false artifacts of the ZCode-injected PATH.

### Step 2 — Create `~/.zprofile` (fixes brew + all brew tools in zsh)
This is the single most important fix. Content:
```sh
# Homebrew (Apple Silicon)
eval "$(/opt/homebrew/bin/brew shellenv)"
```
Verified output of `/opt/homebrew/bin/brew shellenv` (Homebrew 6.0.12) sets `HOMEBREW_PREFIX`, `HOMEBREW_CELLAR`, `HOMEBREW_REPOSITORY`, `FPATH`, `INFOPATH`, and prepends `/opt/homebrew/bin` + `/opt/homebrew/sbin` to PATH. After this, `brew` resolves in any zsh login shell (which is what Terminal.app opens).

### Step 3 — Create `~/.bash_profile` (fixes brew in bash)
Same line:
```sh
# Homebrew (Apple Silicon)
eval "$(/opt/homebrew/bin/brew shellenv)"
```

### Step 4 — Recreate the `claude` CLI shim (fixes `claude`)
The native binary is alive at `~/Library/Application Support/Claude/claude-code/2.1.217/claude.app/Contents/MacOS/claude`. Recreate the missing shim:
```sh
/bin/mkdir -p ~/.local/bin
/bin/ln -sf "/Users/eddie/Library/Application Support/Claude/claude-code/2.1.217/claude.app/Contents/MacOS/claude" ~/.local/bin/claude
```
Then add to `~/.zprofile` (and `~/.bash_profile`) so it's on PATH in every login shell:
```sh
# Claude Code CLI (recreated after ~/.local/bin loss on Jul 19)
export PATH="$HOME/.local/bin:$PATH"
```
**Long-term note:** the symlink pins a version path (`2.1.217`) that will break on the next claude auto-update. The cleaner permanent fix is to re-run the official native installer, which recreates a version-agnostic shim. I'll verify the current installer command from official docs (not memory) before running it, and offer that as an optional follow-up after the shim is working.
